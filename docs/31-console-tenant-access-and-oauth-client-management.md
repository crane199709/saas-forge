# Console 租户访问、冻结与接入凭据管理

**状态：客户体验与范围已于 2026-09-14 经逐项讨论确认，并发布为 [GitHub Issue #181](https://github.com/crane199709/saas-forge/issues/181)，标记 `ready-for-agent`；实现与本机验收记录见 [Issue #181 验证记录](acceptance/issue-181-console-access-management.md)。**

本规格承接 [MVP 开发计划第 2 阶段](16-mvp-development-plan.md)剩余三项 Console 交互。前置的平台登录、Tenant 创建、订阅与管理员初始化复用[已有规格](30-platform-console-tenant-initialization.md)。本文记录本轮 Q1～Q10 的确认结果，不表示第 2 阶段完成。

## 1. 客户目标与范围

| 客户 | 本轮完成后可以做什么 |
|---|---|
| 租户管理员 | 从邮件设置密码，登录并进入可访问的公司；切换公司，刷新后仍能确认自己正在管理哪家公司 |
| 平台管理员 | 冻结公司、解除冻结，重新打开页面后查看未完成操作及下一步处理方式 |
| 租户用户 | 公司被冻结后停止使用受保护功能，闲置页面也及时提示；解除冻结后重新登录 |
| 平台管理员 | 创建客户应用的接入凭据、保存一次展示的 Secret、处理结果不确定、轮换和停用接入 |

本轮“资源上下文”仅指当前 Tenant、Membership、Accessible Membership 候选与已有品牌解析；不新增套餐、额度、组织或 Project 业务页面，也不因“当前 Session”扩大为设备或历史会话管理。客户界面可以使用“公司”等易懂文案，领域归属仍沿用 [Context Map](../CONTEXT-MAP.md)。

Platform Console 对 `RESERVED_SERVICE` 仅展示基本信息；创建、轮换、Secret 替代签发与吊销入口只向 `RUNTIME_SERVICE` 开放。平台自身凭据继续通过运维流程维护。本轮收缩的是 Console 入口，不删除或改变既有后端管理契约。

## 2. 设置密码、登录与切换公司

### 设置密码

- 邮件进入真正的 Tenant Console Password Setup 页面，不能以 Gateway 静态页替代产品路径。
- 设置成功后提示使用新密码正常登录，不自动建立登录会话。
- 链接缺失、失效或不能使用时，说明无法继续设置并引导联系平台管理员；管理员复用已有受限重发入口。
- 提交后未收到明确结果时，显示“设置结果尚未确认”，建议先用刚设置的密码尝试登录，不能断言设置失败或自动重复提交。
- 已有密码的身份不借 Password Setup 重置密码；重发结果不等于邮件已经进入客户收件箱。

### 进入公司与刷新恢复

- 只有一个可访问公司时直接进入；有多个时展示首次选择；没有可访问公司时明确无法进入，不能拿历史候选作为当前资格。
- 进入后清晰展示当前公司及切换入口。刷新、关闭浏览器再打开或重新登录后，从权威状态确认当前会话和上下文；恢复完成前不显示旧公司的受保护内容。
- 恢复遇到网络或服务暂不可用时显示“暂时无法确认”，提供允许的恢复操作，不能误报为密码错误或已经登出。
- 当前公司信息和品牌一起应用；无上下文、切换中或品牌无效时遵守既有完整平台品牌回退规则。

### 切换中及失败

- 从公司 A 切到 B 期间遮蔽 A 的受保护内容并暂停业务操作，直到确认当前公司。
- 确认进入 B 后才显示 B；确认仍在 A 时明确告诉用户；结果未定时显示“正在确认当前公司”。
- 列表显示可进入不保证稍后仍可进入；提交时目标已不可访问，应说明切换未完成并重新读取当前状态。
- 当前访问资格已失效时要求重新登录，不能通过切到另一个公司保住已经失效的会话。
- 切换已提交后不得恢复旧 Token 或旧公司内容；旧标签页与迟到响应不得覆盖新的公司上下文。

## 3. 冻结、解除冻结与失败处理

客户界面必须区分以下操作，不使用同一个“恢复”按钮表达相反结果：

| 操作 | 对客户的含义 | 成功结果 |
|---|---|---|
| 冻结公司 | 停止该公司的访问 | Tenant 为 `SUSPENDED`，原会话失效 |
| 继续完成冻结 | 继续处理尚未完成的冻结 | 完成冻结，仍然不可访问 |
| 解除冻结 | 允许公司重新尝试访问 | Tenant 回到 `ACTIVE`，仍受有效期等规则约束 |

- 平台页面同时呈现公司当前状态、操作进度和允许操作。不能仅凭公司显示 `ACTIVE` 就断言访问未被冻结：安全拒绝可能已生效，而冻结操作尚未完成。
- 冻结、继续冻结和解除冻结中途关闭页面，重新进入后仍可查看处理结果，不按一次网络失败新建相同操作。
- 解除冻结迟迟未完成时明确显示“尚未恢复访问”，提供查看最新结果入口；只有权威状态允许才提供重试，需要运维介入时提供脱敏问题编号。
- 不按页面等待时长自行宣告失败，不把“继续完成冻结”当作解除冻结失败的重试入口，也不把请求已受理说成访问已恢复。
- 保留既有权限：具备权限的 Platform Administrator 可以继续待处理的冻结工作流，不限定为原发起人；OAuth Secret 的原操作者限制不套用到此处。
- 解除冻结不恢复已撤销会话。此前会话已失效的租户用户必须重新登录；公司已到期等情况下仍可能不能进入，界面不能承诺解除冻结必然可用。
- 冻结不禁用 Membership、不释放人数额度，解除冻结也不重建成员关系。

### 闲置页面的主动提示

- 联网且保持运行的页面，即使没有用户操作，也必须在访问冻结生效后最迟 **30 秒**提示访问已失效，并遮蔽受保护内容；从权威安全拒绝生效时开始计时，不从点击冻结按钮开始计时。
- 电脑休眠、浏览器冻结或丢弃标签页、断网期间不承诺提示时限。恢复运行、联网或重新打开页面时，先核验访问资格，再展示受保护内容。
- 前台闲置与可正常调度的后台标签页都纳入验收；若浏览器暂停页面执行，则按恢复时核验验收，不虚构暂停期间的提示证据。
- 下一次业务操作、刷新或重新获得焦点也必须处理失效。主动检查应由共享认证能力统一协调，不让每个页面各自维护一套检测。
- 服务暂不可用时遮蔽受保护内容，显示暂不可用并阻断未确认的受保护操作；只有明确的会话或当前访问上下文拒绝才能宣告失效，普通业务权限拒绝不能一概导致登出。没有明确原因的拒绝只提示“访问已失效”，不猜测为公司被冻结。
- 主动检查不改变会话有效期政策，不以无限 Token 刷新维持闲置会话，不重放冻结或解除冻结命令。

## 4. 客户应用的接入凭据

### 创建与一次展示

- 从正式允许范围中选择接入权限，创建成功后展示 Client 基本信息和一次性的 Secret 展示区。
- 明确提示“关闭后无法再次查看，请妥善保存”，提供用户主动点击的复制按钮。复制失败时如实反馈，不虚报保存成功。
- 不自动复制、不提供下载；关闭展示区、离开页面、刷新或会话失效后清除 Secret，不能重新展开或从浏览器前进后退中恢复。
- 用户主动复制到系统剪贴板是本轮允许的交付方式；应用不将 Secret 写入浏览器持久存储、日志、遥测、URL 或重复读取接口。

### 结果不确定与替代签发

- 创建或轮换没有收到明确结果时显示“结果待确认”。刷新、重启浏览器或重新登录后仍可找到本人操作及允许动作，不能按名称猜测成功，也不能自动再创建一份。
- 已确认签发但没有拿到 Secret 时，由原操作者在原签发成功后的十分钟内，显式执行一次替代签发；旧的未送达 Secret 失效，新 Secret 仍只展示一次。
- 重新打开页面不延长十分钟期限，操作状态读取不返回原 Secret，不自动触发替代签发。
- 已超过补领期限、已经替代签发过或替代响应再次丢失时，明确说明无法找回。引导创建替代接入凭据，不再提供重复补领。
- 替代接入可能需要客户重新配置应用。不能自动停掉仍在使用的旧接入；由管理员确认完成替换后显式停用旧接入。该引导不增加自动迁移或“已验证部署成功”的承诺。

### 轮换与停用

- 常规轮换后新 Secret 立即有效，旧稳定 Secret 在首次轮换提交后 24 小时失效。界面显示权威截止时间，提醒客户在截止前完成应用配置更新。
- 重叠期间不允许再次常规轮换；替代签发不延长旧稳定 Secret 的截止时间。不能用详情更新时间推测截止时间。
- 停用即不可逆吊销整个 Client，明确告知该接入将无法继续使用；不将其描述为可以随时恢复的暂停。
- 吊销后立即拒绝新 Token 签发与已签发 Service Token 的使用，不等待自然过期。被吊销的 Client 仍可查看非敏感详情。

## 5. 权威状态与实现约束

本节将确认的客户体验映射到实现责任，不将内部术语作为普通客户操作步骤。

| 能力 | 权威责任与必要补齐 |
|---|---|
| Password Setup | IAM 拥有凭据建立；Tenant Console 消费正式 operation，邮件 Fragment 读取后立即清除，Challenge 和密码仅内存保留 |
| 当前会话与公司 | 复用 IAM 认证 Runtime 与 Tenant Context 正式读取；现有 Platform Current Session 不能直接用于 Tenant |
| 首次选择与切换 | 首次选择与 Tenant Context Switch 区分；IAM 拥有当前 Family 的切换与恢复，Tenant Access 校验 Membership |
| 冻结与解除冻结 | Tenant Access 补齐耐久生命周期操作的权威读取及允许动作，IAM 保持撤销事实与 Fence 权威 |
| OAuth 未决操作 | IAM 补齐按原操作者授权的非敏感操作发现、结果与恢复资格读取；创建响应丢失且 Client ID 未知时也能发现原操作 |
| 轮换与替代资格 | IAM 提供权威重叠截止、替代签发截止及允许动作，不通过时间戳、Secret 数量或浏览器记录推断 |

沿用 [ADR 0039](adr/0039-consoles-share-one-authentication-runtime.md) 与 [ADR 0045](adr/0045-console-operation-recovery-is-server-authoritative.md)：浏览器不持久化操作请求、恢复材料、Membership 候选或凭据。业务页面只能使用共享类型化 Client；后端应提供满足业务判断的最小公开状态，不暴露租约、数据库阶段或内部撤销请求材料。

恢复读取必须区分处理中、已有结果、明确允许继续和无法确定；找不到记录不等于可以新建。恢复历史操作结果后仍须读取当前资源，不能把过去成功的响应当成当前状态。每次变更重新校验权限，允许动作的显示不能替代服务端授权。

既有冻结自动恢复和解除冻结恢复不同：当前解除冻结失败可以仍在后台处理中，不能直接套用冻结的重试耗尽状态；本轮通过权威进度和允许动作实现用户反馈，不擅自新增取消、跳过安全步骤或自动解封。

客户看到的“问题编号”是脱敏排查引用，优先复用正式 Problem 的 `traceId`，不代表已创建客服工单。后台失败的排查引用若需跨刷新展示，由权威读模型提供，不从异常文本推断。30 秒主动提示的成功时限与服务不可用反馈分别验收，不能把无法核验误报为已确认冻结。

现有 [ADR 0031](adr/0031-tenant-context-switch-targets-the-refresh-session.md)、[ADR 0032](adr/0032-bulk-session-revocation-uses-target-fences.md)、[ADR 0033](adr/0033-oauth-client-management-uses-immediate-revocation-and-replacement-recovery.md) 的安全决策继续有效。Secret 补领与客户重新创建替代接入不是保留服务的部署 Replacement Job。

## 6. 验收场景

产品范围已确认；正式读模型字段、操作发现方式及错误映射需在实现前完成契约设计，不假定已有接口足够。以下项目的勾选必须由直接证据支持；实现与各层验证分别记录。

- [ ] 从全新 Compose 数据卷经真实 Platform Console 创建前置资源、初始化管理员，再从邮件进入 Tenant Console 设置密码并正常登录；覆盖失效链接、重复使用和提交结果不确定。
- [ ] 覆盖一个、多个及无可访问 Membership 的登录结果；完成选择、切换与刷新恢复，当前公司和品牌一致，不出现跨公司内容。
- [ ] 切换时断开响应、目标失效、当前资格失效和并发标签页切换；验证遮蔽、结果确认与迟到响应隔离，不以界面标题变化替代权威上下文证据。
- [ ] Platform Console 冻结及解除冻结成功；冻结中、继续冻结、解除冻结中与失败反馈可区分，页面重开能发现原操作，不重复产生安全副作用。
- [ ] 证明旧 User Token 与 Session 被拒绝，闲置且正常运行的页面在冻结生效后 30 秒内提示并遮蔽；记录实际计时，覆盖前台、后台、断网及休眠恢复。
- [ ] 解除冻结后旧会话仍不可用，重新登录才可恢复符合资格的访问；当前 Tenant 仍到期或不可访问时稳定拒绝。
- [ ] 经 Console 创建 Runtime Client、主动复制一次展示的 Secret；关闭、离开、刷新、会话失效和前进后退后不能重读，保留服务只有只读界面。
- [ ] 创建、轮换响应丢失后，刷新和重启浏览器仍能发现本人操作；覆盖十分钟内一次替代、越权、超时、再次丢失与替代接入引导。
- [ ] 证明轮换重叠窗口内新旧凭据可用、到期后旧凭据被拒绝、替代签发不延长窗口；吊销后拒绝新 Token 与已有 Service Token。
- [ ] 核对浏览器存储、URL、日志及重复读取无 Secret；含 Secret 的截图、录像和网络追踪不得形成泄密验收产物，断言与报告只保留脱敏结果。
- [ ] 复用共享 Design System、认证/错误与中英文语义；默认语言完成完整路径，另一语言覆盖代表性操作，并验证键盘、焦点与无障碍反馈。

真实产品及四域安全使用桌面 Google Chrome 当前稳定版，后端使用 JDK 17。保留本机受影响验证与完整 CI 的区别；Fresh Compose、真实浏览器、契约、安全、迁移与国际化必要验证不能以 Mock、curl 或静态配置检查替代。不得接管开发者维护的本机服务生命周期。
