# 前端设计规范

视觉参考是 [soybean-admin-element-plus](https://github.com/soybeanjs/soybean-admin-element-plus)（MIT），借鉴它的信息结构和克制的样式，代码按本仓库约定重写。线上样板是租户端 `/roles`（`apps/tenant-app/src/role/`）：新页面照它的结构写。

## 改动页面的流程

按顺序走完三步，功能和设计分开做。

### 1. 页面简报

写代码前，在 issue 文件或回复里写清：

- 谁在用，这个页面的**主任务**是什么
- **主操作**是哪一个，低频操作有哪些
- 哪些信息必须一眼看到，哪些收起或删掉
- 用哪种页面原型（见下）

完成标准：新页面或结构性改动经用户确认；只加一个字段或按钮时，说明它放在哪、为什么放那。

### 2. 功能实现

实现行为并跑通单测。这一步只保证功能，样式先用 token 和原型结构搭好。

### 3. 设计走查

这一步做删减、合并和重排，不加功能。

1. 在 `e2e/visual/` 为页面的每个关键状态加用例，mock 数据用接近真实长度的文本，并覆盖空值和最长值。
2. 运行 `pnpm test:visual:update`，用 Read 逐张查看 `e2e/visual/__screenshots__/` 的 PNG（桌面 1440、笔记本 1024 两档）。
3. 对照下面的走查清单，修改后重新截图。

完成标准：每张截图逐项过完清单，`pnpm lint:style` 和 `pnpm test:visual` 通过。基线只在 macOS 生成，变更时一并提交 PNG，并在交付说明里写明哪些截图变了、为什么变。

## 页面原型

页面都落在 `AppLayout` 提供的同一块内容面上，内容面内直接排布，卡片不再嵌套卡片。

| 原型        | 结构                                                                                  |
| ----------- | ------------------------------------------------------------------------------------- |
| 列表        | `PageHeader` → `PageToolbar`（左：筛选或视图切换，右：主操作）→ `el-table` → 右下分页 |
| 详情        | `PageHeader`（右：操作）→ 分组的 `el-descriptions` → 关联数据用 tab                   |
| 表单 / 设置 | `PageHeader` → 按主题分组的表单，内容宽度不超过 `720px`，顶部标签                     |
| 工作台      | `PageHeader` → 指标行 → 主内容                                                        |

一页有多个并列视图时用 `el-tabs`，放在 `PageHeader` 之下。

## 组件选择

- **数据列表**用 `el-table`，分页接口优先用 `ListPage`。列用 `min-width`，长文本加 `show-overflow-tooltip`，操作列 `fixed="right"` 且宽度容得下所有按钮同行。数字列右对齐，状态用 `el-tag`，空值显示 `—`，时间用 `formatDateTime`。
- **编辑**按内容选载体：字段少于 6 个且无嵌套用 `el-dialog`；含权限树、条件组等长内容用 `el-drawer`；需要多步或跨会话用独立页面。尺寸取 `overlaySize` 的档位。
- **确认**不可逆或影响他人的操作用 `el-dialog` 说明影响，可恢复的操作不打断。
- **按钮层级**：每个区域一个实心主按钮，其余用默认或 `plain`，行内操作用 `link`。视图切换用 `plain` 的 `el-button-group`。

## 交互规则

- **新增和编辑走按钮**：列表上方放“新增”，点击后在弹窗或抽屉里填写。列表行保持只读，行内操作只放入口；需要逐行连续改值的配置表（如字典项、参数）除外。
- **层级数据用树形表格**：部门这类有上下级的数据保留层级，不平铺。
- **危险操作不常驻**：不可逆或影响账号归属的操作放进专门的“危险操作”分区，不进顶栏，也不和常用操作相邻；执行前用确认弹窗说明后果，文案避免和常用操作同词。
- **内容按集合展示**：同类记录用表格，正文放详情；时间线式的卡片只用于接收方的消息流（如通知中心）。
- **单一查询页**：输入框和按钮同一行放顶部，未查询时用 `el-empty` 占位。

## 页面上的说明文字

需要说明文字才能看懂，通常说明设计有问题。写之前先归类：

| 文字在说什么                     | 处理                                                  |
| -------------------------------- | ----------------------------------------------------- |
| 这个页面是什么、标题已表达的内容 | 删除                                                  |
| 该怎么填                         | 用控件、校验、占位符解决                              |
| 操作后果                         | 放确认弹窗；没有确认步骤时用 `el-alert`，不用灰色小字 |
| 状态或数据                       | 用标签、提示框或空状态                                |

## 样式

`packages/ui/src/theme.ts` 的 `layoutTokens` 是间距、字号、圆角和页面色的唯一来源，`pnpm lint:style` 校验 `.vue` 和 `.css`。

- 间距的节奏：同组元素 `--forge-space-2`，控件组之间 `--forge-space-3`，区块之间 `--forge-space-4`。
- 文字颜色用 Element Plus 的 `--el-text-color-*`，主内容 regular，辅助说明 secondary，只有区块标题加粗。
- `packages/ui` 用 `h()` 的内联样式，lint 覆盖不到，同样只写 `var(--forge-*)`。

## 走查清单

- 主任务和主操作在首屏一眼可见，主操作只有一个
- 同类元素对齐，左边缘和间距一致，没有一屏多种节奏
- 按钮、标签、表头不折行；操作列同行显示
- 长文本和最长数据不撑破布局，空值有明确表示
- 1024 宽度下主要信息仍可读，操作仍可达
- 层级靠位置和字重表达，同一层级的标题样式一致
- 没有开发者视角的内容（裸枚举值、内部编码）无说明地露给用户
- 没有用灰色小字解释页面或填写方式，新增入口和危险操作符合交互规则
- 删掉任一元素页面都会变差；否则删掉
