# Sub-App 页面规范

基于 SaaS Forge 平台开发 Sub-App（挂在平台主应用中的业务前端）时，新增或调整页面必须遵守的规则。本文随脚手架复制进生成的工程，平台升级改动规则时以 CHANGELOG 为准重新复制。

页面组件（`PageHeader`、`PageToolbar`、`ListPage`、`overlaySize`、`formatDateTime`）与 `--forge-*` 样式 token 由平台的 `@crane199709/ui` 提供；页面都落在主应用布局提供的同一块内容面上。

## 接口入口

业务请求经共享 SDK 的 `client.api()` / `client.page()`，源码仍使用网关路径（如 `/orders/orders`）；SDK 强制添加 `/api`，Shell 剥离入口段后转发网关。开发 Shell、生产 Shell 与独立宿主固定代理 `/api` 和 `/iam`，新增服务不追加代理配置；Sub-App 配置不再接受 `apiPrefixes`。登录、OAuth2 回调与 Refresh 保持 `/iam` 原路径及 Cookie 语义。Shell、SDK 与 sub-app-kit 须配套升级，跨源业务路径仍拒绝。

后端服务统一通过自己的 `FORGE_OPS_TOKEN`、`FORGE_MANIFEST_TOKEN` 配置凭证，Platform 的运维映射集中维护。Sub-App 继续使用 Shell 提供的用户会话；服务端凭证不进入 Vite 环境变量、浏览器配置或联邦产物。

## 敏感字段展示

敏感字段的路径、分级与默认规则由 Business Service 的 Resource Manifest 登记。列表、详情与导出消费服务端统一脱敏后的值；确需查看原文时调用业务服务单独授权并审计的专用操作，页面权限与数据分级不能直接让服务返回原文。

## 改动页面的流程

按顺序走完三步，功能和设计分开做。

### 1. 页面简报

写代码前，在工单或回复里写清：

- 谁在用，这个页面的**主任务**是什么
- **主操作**是哪一个，低频操作有哪些
- 哪些信息必须一眼看到，哪些收起或删掉
- 用哪种页面原型（见下）

完成标准：新页面或结构性改动经需求方确认；只加一个字段或按钮时，说明它放在哪、为什么放那。

### 2. 功能实现

实现行为并跑通单测。这一步只保证功能，样式先用 token 和原型结构搭好。

### 3. 设计走查

这一步做删减、合并和重排，不加功能。

1. 在 `e2e/visual/` 为页面的每个关键状态加用例：在 `localStorage` 预置假会话，用 `page.route` mock 接口；mock 数据用接近真实长度的文本，并覆盖空值、最长值和空列表。
2. 运行 `pnpm test:visual:update`，逐张查看生成的截图 PNG（桌面 1440、笔记本 1024 两档）。
3. 对照下面的走查清单，修改后重新截图。

完成标准：每张截图逐项过完清单，`pnpm lint:style` 和 `pnpm test:visual` 通过。基线 PNG 与代码一同提交，截图与运行平台有关，团队固定在同一平台生成；变更时在交付说明里写明哪些截图变了、为什么变。

## 页面原型

页面内容面内直接排布，卡片不再嵌套卡片。

| 原型        | 结构                                                                                  |
| ----------- | ------------------------------------------------------------------------------------- |
| 列表        | `PageHeader` → `PageToolbar`（左：筛选或视图切换，右：主操作）→ `el-table` → 右下分页 |
| 详情        | `PageHeader`（右：操作）→ 分组的 `el-descriptions` → 关联数据用 tab                   |
| 表单 / 设置 | `PageHeader` → 按主题分组的表单，内容宽度不超过 `720px`，顶部标签                     |
| 工作台      | `PageHeader` → 指标行 → 主内容                                                        |

一页有多个并列视图时用 `el-tabs`，放在 `PageHeader` 之下。

## 组件选择

- **数据列表**用 `el-table`，分页接口优先用 `ListPage`。列用 `min-width`，长文本加 `show-overflow-tooltip`，操作列 `fixed="right"` 且宽度容得下所有按钮同行。数字列右对齐，状态用 `el-tag`，空值显示 `—`，时间用 `formatDateTime`。
- **编辑**按内容选载体：字段少于 6 个且无嵌套用 `el-dialog`；含权限树、条件组等长内容用 `el-drawer`；需要多步或跨会话用独立页面。尺寸取 `overlaySize` 的档位。
- **确认**不可逆或影响他人的操作用 `el-dialog` 说明影响，可恢复的操作不打断。
- **按钮层级**：每个区域一个实心主按钮，其余用默认或 `plain`，行内操作用 `link`。视图切换用 `plain` 的 `el-button-group`。

## 交互规则

- **新增和编辑走按钮**：列表上方放“新增”，点击后在弹窗或抽屉里填写。列表行保持只读，行内操作只放入口；逐行即改即生效的设置表（如参数）除外。
- **层级数据用树形表格**：部门这类有上下级的数据保留层级，不平铺。
- **危险操作不常驻**：不可逆或影响账号归属的操作放进专门的“危险操作”分区，不进顶栏，也不和常用操作相邻；执行前用确认弹窗说明后果，文案避免和常用操作同词。
- **内容按集合展示**：同类记录用表格，正文放详情；接收方阅读的消息流（如通知中心）用单行消息列表：未读标记、标题、摘要、时间、操作，点击整行展开全文。
- **单一查询页**：输入框和按钮同一行放顶部，未查询时用 `el-empty` 占位。

## 页面上的说明文字

需要说明文字才能看懂，通常说明设计有问题。写之前先归类：

| 文字在说什么                     | 处理                                                  |
| -------------------------------- | ----------------------------------------------------- |
| 这个页面是什么、标题已表达的内容 | 删除                                                  |
| 该怎么填                         | 用控件、校验、占位符解决                              |
| 操作后果                         | 放确认弹窗；没有确认步骤时用 `el-alert`，不用灰色小字 |
| 状态或数据                       | 用标签、提示框或空状态                                |

## 样式

`--forge-*` token 是间距、字号、圆角和页面色的唯一来源，不写字面量；`pnpm lint:style` 校验 `.vue` 和 `.css`。

- 间距的节奏：同组元素 `--forge-space-2`，控件组之间 `--forge-space-3`，区块之间 `--forge-space-4`。
- 文字颜色用 Element Plus 的 `--el-text-color-*`，主内容 regular，辅助说明 secondary，只有区块标题加粗。

## 代码格式

格式交给 Prettier，规则与平台前端同一份：`.prettierrc.json` 随平台版本复制，不在本工程修改；`docs/standards/` 已列入 `.prettierignore`。提交前 `pnpm format:check` 必须通过，`pnpm format` 按规则改写。

## 走查清单

- 主任务和主操作在首屏一眼可见，主操作只有一个
- 同类元素对齐，左边缘和间距一致，没有一屏多种节奏
- 按钮、标签、表头不折行；操作列同行显示
- 长文本和最长数据不撑破布局，空值有明确表示
- 1024 宽度下主要信息仍可读，操作仍可达
- 层级靠位置和字重表达，同一层级的标题样式一致
- 没有开发者视角的内容（裸枚举值、内部编码）无说明地露给用户
- 没有用灰色小字解释页面或填写方式，新增入口和危险操作符合交互规则
- 删掉任一元素页面都会变差；否则删掉
