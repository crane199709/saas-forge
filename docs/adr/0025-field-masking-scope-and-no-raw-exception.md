# 字段脱敏只覆盖导出、日志与声明的在线接口，不提供自动原文例外

业务数据的敏感字段采用“Manifest 声明 + 分级 + 规则”的字段级脱敏，与行级 Data Policy 正交：Data Policy 决定能看到哪些行，字段脱敏决定能看到的字段值。Manifest 增加敏感字段声明（字段路径、数据分级、默认规则）；分级固定为 L1–L4，平台预置脱敏规则、Tenant 可覆盖规则，但规则只能由固定策略库组合，不接受任意正则或脚本。L4 字段默认禁止导出。

脱敏在三条通道执行：导出走 SDK 导出管线（缺失策略时任务失败）、日志走 Logback converter（不输出原值并告警）、在线接口走 Jackson 序列化（只覆盖 Manifest 声明的字段，缺失规则时整次响应失败）。不做“按角色直接返回原文”的自动例外；业务确需展示原文时，由该服务提供专用操作、单独授权并写审计。启动与保存规则时校验引用，被引用的规则不能删除。

选择这个边界，是因为 icube-base 的现状也只覆盖导出与预览，在线统一脱敏在 icube-base 的 ADR 0009 中明确未解决；全链路在线脱敏要改大量 DTO、查询与搜索，并让分级承担访问控制的职责。角色级脱敏豁免已被 icube-base 退役，专用操作比序列化层放行更可审计。

## Considered Options

- 全链路在线脱敏（网关或序列化层统一）：改动面大，性能与搜索一致性难保证，且分级会与 ABAC 重叠。
- 按角色或权限码自动返回原文：配置分散、审计粒度粗，容易变成事实上的“脱敏开关”。
- 只做导出与日志，不做在线：合规展示场景不够，最终仍要逐接口补。

## Consequences

- Resource Manifest 增加敏感字段声明，改动需升 `forge.manifest.version`。
- 在线脱敏只覆盖声明字段，未声明字段不会自动脱敏，登记完整性由服务负责。
- 原文查看下沉到各业务服务的专用操作，平台不提供通用入口。
- 日志脱敏失败只影响该条日志，不阻断业务请求；导出与在线脱敏失败则显式报错。
