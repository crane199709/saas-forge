# Permission 撤权成功后新请求立即采用新权限

2026-10-14 第 4 阶段设计访谈确认：角色解绑、Role-Permission 删除等撤权操作成功返回后，随后开始的请求必须采用新的权威权限判定；不追溯回滚已进入执行的请求。该边界覆盖 Gateway、SDK 与业务服务端的 Permission 判定，菜单隐藏不构成服务端拒绝证据。

本决策选择明确的撤权完成边界，而非容忍短 TTL 内的旧授权。MVP 每次服务端 Permission 判定均同步查询权威结果，本地缓存不独立放行请求；权威不可用时拒绝放行并返回可重试错误。Kafka 仅用于展示刷新等辅助失效，不作为撤权生效前提。后续授权缓存优化须在正确性与实测基础上另行设计，不属于本阶段默认实现。

该选择可能增加请求路径的同步校验与可用性成本，性能须通过实现验证，不在此承诺延迟指标。它不改变 Feature 的独立判定或已有 Membership 禁用的 Fence/会话撤销边界，也不表示 Permission Runtime 已实现。
