# 导入回滚只恢复被覆盖的旧值，冲突默认阻断

覆盖导入在写库前保存将被覆盖数据的快照；回滚只把被覆盖的旧值恢复，不删除该次导入新增的数据，也不等同于 Restore。回滚前检查记录在导入后是否又被修改或被后续导入覆盖：发现冲突时返回冲突报告并默认阻断；管理员显式确认后可跳过冲突记录、回滚其余，冲突记录永不自动覆盖。回滚按记录执行、失败可重试、已恢复的不重复；快照保留 90 天，可由服务调整。

选择“只恢复旧值”是因为删除新增行会破坏下游引用、审计与事件，并与 Restore 的语义混淆；icube-base 的 ImportBackup 也采用同一口径。整单全有或全无在万行导入时几乎不可用，因此保留“确认后跳过冲突”的例外，但默认仍然阻断。

## Considered Options

- 全量撤销（删除新增 + 恢复旧值）：删除会破坏引用，且无法区分“导入新增”和“导入后业务新增”。
- 不检查冲突、快照强制覆盖：会静默覆盖别人后来的修改。
- 整单全有或全无：实现简单，但一条冲突就会让整个回滚不可用。

## Consequences

- 导入任务与回滚需要备份表与冲突报告接口，回滚写独立审计。
- 回滚权限与导入权限分离，默认只给管理员。
- 快照过期后只能人工处理，不保留“永久可回滚”的承诺。
