# 菜单不是授权单位，角色授权界面是 Permission Code 的菜单树视图

租户希望「按角色勾选菜单」时，我们不在 Role 上增加独立的菜单可见性维度，Permission Code 仍是唯一的功能授权单位：授权界面按 Resource Manifest 的菜单树（叶子菜单下列出页面内的操作权限码）组织 Permission Code，勾选菜单即授予它挂的权限码。原因是菜单可见性不是访问控制：隐藏菜单挡不住持有同一权限码的接口调用，若要让菜单成为访问边界，它就必须一路影响到接口鉴权，这正是 Permission Code 的职责。需要分开控制挂同一权限码的多个菜单时，由业务服务拆分权限码（清单可声明只用于前端的权限码）。

## Considered Options

- 角色-菜单关联表，最终可见 = 有权限码且菜单被勾选：同一权限码下的菜单可以分开隐藏，但隐藏只是界面整洁，形成两套授权维度且后者不是安全边界，管理员容易误以为已禁止访问。
