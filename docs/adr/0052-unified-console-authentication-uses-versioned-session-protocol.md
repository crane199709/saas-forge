# 单 Console 使用版本化的统一会话协议

> 状态：accepted。2026-09-15 确认协议；#204 已实现 v2，#203 已交付固定版本 Client，统一前端已独立迁移。部署默认仍关闭统一协议，是否切换以实际环境为准；执行步骤见[#204 受控切换](../acceptance/issue-204-unified-console.md#受控切换)。#207 只清理旧入口，不授权停用外部消费者或修改历史基线。

统一 Console 在常规密码验证后从权威来源取得平台与公司候选，不在登录前选择 Intent。同一浏览器只有一个当前 Identity 和当前工作上下文；多个候选在“平台管理”“公司工作台”分组卡片直接选择。无权限时保留不能访问业务的等待会话；Initial Credential Session 仍只允许首次改密。当前上下文权限失效、整体退出均终止当前 Family，不能保留另一管理视图的有效 Token。

认证以显式 v2 交付，一个 Slot 定位 Cookie 与一个轮换 Refresh Cookie 定位同一会话。Slot 的服务端当前指针、版本前置条件、可恢复切换/退出及全部 JTI 撤销保证单一会话；前端锁与响应代次不能代替这些边界。采用额外定位 Cookie 的成本，是为并发登录和退出失败后仍能恢复原会话的结束流程；不把它当成独立访问凭证，不保存明文 Refresh Token。详情与公开案例见[统一认证协议](../unified-authentication-protocol.md)。

新版启用时直接停用旧浏览器认证，不保留旧登录并行，也不迁移旧 Family 权限。这是显式退役的破坏性发布，不是扩大 ADR 0038 的一次性 v1 豁免；历史基线、已执行迁移保持不可变。回退只选择仍支持统一协议的组合，否则进入维护；重开旧登录需单独确认。该决策替代 ADR 0027/0038 的旧 Intent/双槽位目标、ADR 0031 的仅 Tenant 间切换限制，以及 ADR 0039/0051 的双 Console 目标；权威授权、每 Realm 一个 Runtime、Cookie/CSRF 与固定版本 Client 的边界继续有效。

后端、前端分别交付和验证。前端使用已有 saas-forge-web 的完整 Soybean 固定提交 `7613bd206cd42001b40e3eafceeb895dcbc277a8`，只迁移业务与必要适配，不恢复 #190–#200 的旧双 Console 计划。未受控切换的环境仍保持 v1 行为；已切换环境不得因清理或回退而重开旧登录。
