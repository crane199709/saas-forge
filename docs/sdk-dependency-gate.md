# SDK 依赖与中间件门禁

门禁在 Maven `validate` 阶段检查 POM 声明的直接依赖；未被 Java 代码引用以及 `optional`、`test`、`provided` 依赖同样受检。依赖的版本由现有 BOM 管理，本门禁不改变运行时依赖图。

## 两层检查

- `forge-dependencies` 的 `enforce-middleware-boundary` 禁止直接引入下表原生客户端；以它为父 POM 的业务服务、SDK 与平台服务均继承。仅 import BOM 不会继承构建插件，业务工程应沿用脚手架的父 POM 配置。
- `forge-sdk` 的 `enforce-sdk-dependency-allowlist` 只放行本模块 `forge.sdk.allowedDependencies` 中列出的直接依赖。值为逗号分隔的 `groupId:artifactId`，支持换行；漏配时默认不允许任何直接依赖。
- 两层规则均为 `searchTransitive=false`。Boot Redis、Spring Cloud Nacos 与 Forge starter 带入的传递依赖继续可用，不检查第三方库内部依赖。
- `forge.middleware.skip=true` 只豁免中间件直引检查，不能绕过 SDK 白名单。例外必须在模块 POM 属性旁注释原因，并同步本页。
- 模块循环、包级循环以及代码结构仍由现有 ArchUnit 规则负责。

| 禁止直接引入的坐标                           | 支持的入口                                                                       |
| -------------------------------------------- | -------------------------------------------------------------------------------- |
| `org.springframework.data:spring-data-redis` | `spring-boot-starter-data-redis`，结合 `forge-sdk-tenant` / `forge-sdk-security` |
| `org.redisson:*`                             | `spring-boot-starter-data-redis`，结合 Forge 的 Redis 能力                       |
| `io.lettuce:*`                               | 同上，由 Boot starter 带入客户端                                                 |
| `redis.clients:jedis`                        | 同上                                                                             |
| `org.apache.rocketmq:*`                      | `forge-sdk-mq`                                                                   |
| `com.alibaba.nacos:*`                        | Spring Cloud Nacos discovery / config starters                                   |
| `com.xuxueli:xxl-job-*`                      | `forge-sdk-scheduling`                                                           |

白名单表达允许的依赖方向，不要求所有模块彼此独立。例如 IO 可使用 ABAC、Audit、Reference Data、Scheduling、Security、Storage 与 Web；Storage 可使用 Provisioning；Provisioning 可使用 MQ。

## 平台与其他模块的豁免状态

当前真实模块仅 `forge-sdk-mq` 与 `forge-sdk-referencedata` 设置 `forge.middleware.skip=true`。下列平台服务均保持默认门禁，不因平台身份整体豁免。

| 模块                                              | 中间件豁免 | 原因与入口                                                                      |
| ------------------------------------------------- | ---------- | ------------------------------------------------------------------------------- |
| `forge-gateway`                                   | 否         | Redis 使用 Boot starter；Nacos discovery/config 使用 Spring Cloud starters。    |
| `forge-iam`                                       | 否         | Redis 使用 Boot starter；Nacos 使用 Spring Cloud starters；消息使用 Forge SDK。 |
| `forge-platform`                                  | 否         | Redis 使用 Boot starter；Nacos 使用 Spring Cloud starters；消息使用 Forge SDK。 |
| `examples/demo-service`                           | 否         | 作为业务服务示例，使用受支持的 starter，保持与生成工程相同的门禁。              |
| `forge-architecture`                              | 否         | 仅提供 ArchUnit 规则，无原生中间件客户端。                                      |
| `forge-service-archetype`                         | 否         | 生成业务工程；模板继承 `forge-dependencies`，不设置豁免。                       |
| `forge-dependencies`、`forge-parent`、`forge-sdk` | 否         | BOM / 聚合父模块不直接引入原生中间件；负责向子模块继承检查。                    |

## 修改依赖时

1. 在模块 POM 添加依赖，运行 `validate` 查看门禁结果。
2. SDK 新增合理依赖时审查方向，更新该模块 `forge.sdk.allowedDependencies` 和本页完整清单。不要为了通过构建加入宽泛通配符。
3. 原生中间件确需由实现模块承载时，在 POM 属性旁写明原因、显式豁免，并更新本页豁免记录；业务服务继续从受支持的 starter 接入。
4. 运行对应模块验证与下述行为回归。修改 SDK 时还须运行相关 ArchUnit 测试，确保依赖方向变化没有引入环。

## 门禁行为回归

持久 fixture 位于 `backend/src/it/sdk-dependency-gate/`，仅由根 POM 的 `sdk-dependency-gate` profile 加入 reactor，不参与日常构建。各 fixture 的 `relativePath` 直接指向当前源码的 `forge-dependencies` 或 `forge-sdk`，并使用 `${revision}`；避免本地仓库中旧父 POM 导致假绿。

从仓库根目录运行：

```bash
python3 backend/src/it/sdk-dependency-gate/check.py
# 已有完整 Maven 缓存的本地环境
python3 backend/src/it/sdk-dependency-gate/check.py --offline
# 迭代时只跑指定场景，可重复 --case
python3 backend/src/it/sdk-dependency-gate/check.py --offline --case sdk-exempt-still-enforces-allowlist
```

脚本执行 15 项行为检查：默认 reactor 排除 fixture；Redis/Nacos starter 正例；七类原生客户端直接、optional、test 声明与显式豁免；SDK 多项逗号白名单及 Redis 传递依赖正例；白名单外、漏配、optional、test、provided、非 SDK 平台模块依赖负例；豁免配合白名单成功、豁免仍拒绝名单外依赖。

负例同时检查非零退出码、具体 Enforcer execution、`BannedDependencies` 规则、违规模块与依赖坐标，以及 starter 或更新白名单的提示。下载错误、父 POM 无法解析或缺少 fixture 不算通过。正例还检查对应 execution 确实执行并通过；豁免样例检查中间件规则跳过、SDK 白名单继续执行。

`backend-quality.yml` 在原有 `install -Parchetype-it` 后运行同一脚本，默认联网；失败时连同测试报告上传 `backend/target/sdk-dependency-gate/*.log`。该路径已属于 CI 的后端测试范围，不额外触发前端或集成流程。

可用 Maven 的属性覆盖验证断言对门禁退化敏感；下列两条都应以非零退出，报告“违规依赖应导致构建失败”：

```bash
MAVEN_ARGS='-Dforge.middleware.skip=true' python3 backend/src/it/sdk-dependency-gate/check.py --offline --case middleware-direct
MAVEN_ARGS='-Dforge.sdk.allowedDependencies=*:*' python3 backend/src/it/sdk-dependency-gate/check.py --offline --case sdk-outside-allowlist
```
