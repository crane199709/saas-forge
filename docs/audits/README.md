# 审计报告

本目录存放对仓库自身的一致性审计报告：找出文档、配置与实现互相矛盾的地方，并给出处置建议。

## 怎么读这里的文档

审计报告是**时点快照**，不是现状说明。报告里的"真实情况"是审计当时的状态，其中的问题很可能已经被修复。把报告当成"当前事实"来读，和读一份过期的设计文档一样危险。

判断实现现状请按 [AGENTS.md](../../AGENTS.md) 的文档权威顺序取证：代码与配置 → `GLOSSARY.md`/ADR → README 当前状态 → `docs/NN-*` 设计文档。每份报告文首会写明审计基线与已落地的批次。

## 与 `docs/archive/` 的区别

- `docs/archive/`：**载体已被删除**的历史文档，整体失效，只能追溯。
- `docs/audits/`：对**仍然存活**的仓库做的体检记录，问题多数可修，修完报告本身仍有参考价值。
