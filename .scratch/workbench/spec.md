# 工作台规格

Status: resolved

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准：Workbench、Shell Page、Shell App、Sub-App、Todo、Notification、Announcement。本规格不单独记录 ADR，因为页面合并可回退。

## 问题陈述

租户端首页目前是一个脚手架自检页：欢迎语、当前身份/租户、`identityId`/`tenantId`/`membershipId`，并调用 demo-service 的 `/demo/context` 证明租户上下文。它不是产品首页：

- 用户登录后看不到要处理的事情；
- 身份 ID 对日常使用没有价值，还依赖示例服务；
- 顶栏已经显示身份名与租户名，首页重复展示；
- 待办、通知、公告分散在各自页面，首页没有聚合入口。

## 解决方案

把首页合并进工作台：

- `/` 直接渲染工作台；
- 只保留“姓名 · 租户”的问候语；
- 首屏三张卡：我的待办（前 5 条）、未读通知（数量 + 前 5 条）、最新公告（前 3 条）；
- 前端并行调用现有接口，手动刷新，不做轮询/SSE，不做卡片配置；
- 身份 ID 等会话信息移到「账号安全」页的“当前会话”；
- 移除 `/demo/context` 调用，租户链路继续由 E2E 覆盖。

## 用户故事

1. 作为租户成员，我想在登录后看到问候语和当前租户，以便确认自己在正确的租户里。
2. 作为租户成员，我想看到待办的前 5 条，以便一进来就知道要处理什么。
3. 作为租户成员，我想点击待办跳到对应 Sub-App，以便直接处理。
4. 作为租户成员，我想看到未读通知数量，以便判断是否需要打开通知中心。
5. 作为租户成员，我想看到最新几条未读通知，以便快速了解发生了什么。
6. 作为租户成员，我想看到最新公告，以便了解租户或平台的通知。
7. 作为租户成员，我想手动刷新工作台，以便处理完待办后更新列表。
8. 作为无权限的成员，我不想看到无权限的卡片，以便界面不出现空壳。
9. 作为租户成员，我想在卡片加载失败时看到错误提示，以便知道是网络还是权限问题。
10. 作为租户成员，我想在切换租户后看到新租户的工作台，以便不会看到上一个租户的数据。
11. 作为租户成员，我想在账号安全页看到当前会话的身份、租户与成员 ID，以便排障时提供。
12. 作为开发者，我想让首页不再依赖 demo-service，以便示例服务下线不影响产品首页。
13. 作为平台运营人员，我想让运营端首页保持不变，以便本次只改租户端。

## 实现决策

- 租户端 `/` 直接渲染工作台，原首页组件合并或替换；不再保留独立的身份信息表。
- 问候语只展示当前 Membership 的身份名与租户名，不展示任何 ID。
- 三张卡复用现有接口：
  - 待办：现有待办列表接口，取前 5 条；
  - 通知：现有未读数与列表接口，显示数量与前 5 条；
  - 公告：现有公告列表接口，取最新 3 条。
- 进入页面时并行加载三个接口；提供手动刷新；不做轮询、SSE 或自动刷新。
- 每张卡按对应 Permission Code 决定是否显示：待办 `todo:read`、通知 `notification:read`、公告 `announcement:read`；无权限时整卡隐藏且不请求数据，不显示空状态。
- 现有成员读取接口原先没有独立读取权限。2026-11-13 经需求方确认，新增上述三种权限码，并同步后端鉴权、Resource Manifest / 权限目录、角色授权与套餐配置；通知中心、通知铃铛等已有读取入口同步遵守这些权限，公告管理继续独立使用 `announcement:manage`。
- 通过新增迁移兼容已有租户、角色和套餐的读取能力，避免升级后普通成员意外失去原有入口；后续撤销角色或套餐中的读取权限后立即按现有权限刷新机制生效，不绕过套餐裁剪。
- 卡片项可深链到对应 Sub-App 或通知中心、公告页；无链接时只展示文本。
- 加载、空、错误三种状态分别处理；单个接口失败不阻塞其他卡片。
- 身份 ID、租户 ID、Membership ID 移到账号安全页新增的“当前会话”卡片；账号安全页仍属于 Shell Page。
- 移除首页对 `/demo/context` 的调用；租户上下文校验保留在主链路 E2E。
- 运营端首页不在本次修改范围。
- 不新增后端聚合接口；不新增工作台数据表。读取权限使用现有授权模型，不建立第二套权限体系。

## 测试决策

- 好的测试只验证外部行为：页面渲染的卡片、问候语、权限隐藏、错误状态与跳转；不直接断言组件内部请求顺序。
- 首选接缝是租户端组件测试：用现有 mocked TenantClient 提供待办、通知、公告，断言三张卡与权限分支。
- 真实链路用一条 Playwright 用例：登录、看到问候语与三张卡、点击待办跳转、切换租户后刷新。
- 账号安全页的“当前会话”用组件测试覆盖字段展示，避免暴露到首页。
- 参考现有测试：`App.spec.ts`、`NotificationCenter.spec.ts`、`main-flow` E2E。
- 视觉回归：工作台首屏新增或更新基线截图，覆盖桌面与窄屏。

## 不在范围

- 运营端工作台。
- 可配置卡片、卡片排序或卡片注册协议。
- 后端 BFF 聚合接口。
- 个人日程、日历卡片。
- 轮询、SSE 或实时推送。
- 工作台数据导出。

## 补充说明

- 首页合并后，“工作台”是 Glossary 中的 Workbench，不再使用“首页”称呼。
- 身份 ID 属于排障信息，放在账号安全页；开发者仍可在诊断页看到技术信息。
- 待办与通知的权限、套餐裁剪沿用现有接口行为，工作台不重复判断业务规则。
