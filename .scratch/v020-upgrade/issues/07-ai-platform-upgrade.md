# 07: ai-platform 实际升级与隔离验收

**What to build:** ai-platform 维护者可以从工程实际使用的版本升级到候选版本，保留既有业务能力，并取得后端、scheduling 接入和 Sub-App 的实际升级改动与隔离验收结果。范围以[规格](../spec.md)为准。

**Blocked by:** 01 候选制品新建工程接入验收

**Status:** ready-for-agent

- [ ] 实施时核对 ai-platform 的实际提交、工作区状态、后端及前端依赖、已执行迁移和本地包替代配置，记录基线；不将其假定为已发布的 0.1.0 工程。
- [ ] 在本仓库自己的升级分支合并改动，保留用户已有修改、业务实现、自定义配置和迁移历史，不自动重新生成工程。
- [ ] 后端和 Sub-App 消费与平台验收对应的候选制品，对齐配套版本；按实际来源调整快照或临时包替代项，保留可复现安装方式。
- [ ] 合入必要的配置、检查工具、规范与接入说明；按实际使用能力处理迁移及 SDK/API 差异，不引入未使用的 IO、storage 能力。
- [ ] 在隔离环境复用现有产品验证接缝，验证后端启动、代表性业务请求、权限与租户隔离，以及受本次升级影响的 scheduling 接入行为。
- [ ] Sub-App 的相关构建与检查通过，独立开发宿主和配套 Shell 挂载均完成浏览器验收，业务请求及主题符合约定并查看相关截图。
- [ ] 将实际差异、必改项和问题回填通用升级说明；本票在候选可用后即可开展，无需等待通用样例全部完成，发布准备由汇总工单统一核对。
- [ ] 记录升级分支、工程基线、候选版本与摘要、执行结果及真实服务、runner 或模型调用的验证边界；不将替代接缝描述为未执行的真实联调。
