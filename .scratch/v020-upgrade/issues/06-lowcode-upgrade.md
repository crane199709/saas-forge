# 06: lowcode 实际升级与隔离验收

**What to build:** lowcode 维护者可以从工程实际使用的版本升级到候选版本，保留已有低代码业务与文件关联，并获得后端及 Sub-App 的实际升级改动和隔离验收结果。范围以[规格](../spec.md)为准。

**Blocked by:** 01 候选制品新建工程接入验收

**Status:** ready-for-agent

- [ ] 实施时核对 lowcode 的实际提交、工作区状态、后端及前端依赖、已执行迁移和本地包替代配置，记录基线；不将其假定为已发布的 0.1.0 工程。
- [ ] 在本仓库自己的升级分支合并改动，保留用户已有修改、业务代码、自定义配置及迁移历史，不自动覆盖工程。
- [ ] 后端和 Sub-App 消费与平台验收对应的候选制品，对齐配套版本；按实际来源调整临时包或快照替代项，保留可复现安装方式。
- [ ] 审阅并合入必要的配置、检查工具、规范与接入说明；storage 升级按本工程已有结构和实际差异处理，只新增缺失迁移。
- [ ] 在隔离环境验证后端启动、已有业务数据及文件关联的代表性读写行为、权限和租户隔离，不操作正在使用的共享数据。
- [ ] Sub-App 的相关构建与检查通过，独立开发宿主和配套 Shell 挂载均完成浏览器验收，业务请求及主题符合约定并查看相关截图。
- [ ] 将实际差异、必改项和问题回填通用升级说明；本票在候选可用后即可开展，无需等待通用样例全部完成，发布准备由汇总工单统一核对。
- [ ] 记录升级分支、工程基线、候选版本与摘要、执行结果和验证边界；候选变化影响本工程时更新对应证据。
