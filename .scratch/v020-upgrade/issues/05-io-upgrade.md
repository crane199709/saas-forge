# 05: IO 增量升级与已有任务验证

**What to build:** 已接入 IO 的维护者可以根据当前结构补齐必要的增量升级，并通过独立旧版样例确认已有任务、业务数据及相关导入导出行为在升级后符合契约。范围以[规格](../spec.md)为准。

**Blocked by:** 02 已有 Business Service 升级与数据保留

**Status:** ready-for-agent

- [ ] 复用服务升级验证入口，使用已发布旧版制品建立独立 IO 样例，记录实际 SDK、数据库和候选制品基线。
- [ ] 升级前通过已有业务入口建立代表性的任务、业务数据和所需文件，保留任务状态及业务结果作为升级前证据。
- [ ] 按现有能力、结构和迁移历史补齐所需增量迁移，保持已有迁移不变，不重复执行已完成的升级，不向默认脚手架增加 IO。
- [ ] 升级后通过业务入口验证已有任务及业务数据可用，相关导入导出和任务行为符合约定；覆盖本次实际涉及的任务或快照升级要求。
- [ ] 按样例实际使用的能力验证相应 SDK/API 调整，包括涉及前端任务列表或确认入口时的配套调用；不把本票变成新增业务功能。
- [ ] 复用已有数据库、Redis、存储和 HTTP 接缝，在隔离环境提供可重复的升级验证入口、失败诊断和按能力选择的升级说明。
- [ ] 记录制品来源、候选、数据及迁移保留结果和未覆盖范围；本票可与 storage 样例验证并行，不依赖其完成状态。
