# 04: storage 增量升级与已有文件验证

**What to build:** 已接入 storage 的维护者可以根据当前结构选择必要的增量升级步骤，并通过独立旧版样例证明升级后已有文件、业务引用和相关存储行为符合契约。范围以[规格](../spec.md)为准。

**Blocked by:** 02 已有 Business Service 升级与数据保留

**Status:** ready-for-agent

- [ ] 复用服务升级验证入口，使用已发布旧版制品建立独立 storage 样例，记录实际 SDK、数据库和候选制品基线。
- [ ] 在升级前通过业务和存储入口准备真实存储对象、元数据及代表性业务引用，记录升级前的可观察结果。
- [ ] 根据已有结构及迁移记录选择缺失的 SDK 增量迁移；不重放已完成升级，不改已执行迁移，不将可选能力加入默认脚手架。
- [ ] 在既有隔离数据库与 S3 兼容测试接缝中完成升级，通过业务入口验证已有文件和引用按升级契约可用，相关存储行为通过。
- [ ] 检查本次涉及的用途、生命周期或引用语义变化，分别说明旧数据保留方式和需要项目自行补充的信息，不依猜测给旧文件分类。
- [ ] 提供按能力和当前结构选择步骤的 storage 升级说明、可重复执行入口及诊断材料，记录数据与迁移保留的验证结果。
- [ ] 记录输入制品、候选、执行结果和供应商及跨服务验证边界；与 IO 场景独立验收，不以其他样例成功代替本票结果。
