# 03: 已有 Sub-App 升级与宿主接入

**What to build:** 已有 Sub-App 的维护者可以按升级清单，将使用已发布 `0.1.0` 制品创建的业务前端升级到候选版本，保留自有页面与路由，并在独立开发宿主和配套 Shell 中正常运行。范围以[规格](../spec.md)为准。

**Blocked by:** 01 候选制品新建工程接入验收

**Status:** resolved

- [x] 使用已发布 `0.1.0` 制品生成固定旧版基线，保留代表性业务页面、路由和自定义配置，记录旧版及候选制品来源与摘要。
- [x] 将 SDK、UI、kit 与配套 Shell 对齐，共享依赖按配套版本表精确锁定，更新安装结果；不承诺跨平台版本混合运行。
- [x] 审阅参考工程并合并必要的构建、检查、开发宿主、启动脚本和规范差异，不覆盖自有业务代码或路由语义。
- [x] 移除旧的 apiPrefixes 配置及相关逐服务代理项；通过浏览器业务请求验证统一接口入口，业务源码路径、网关服务前缀和认证路径保持约定。
- [x] 安装、构建、类型、样式、格式及相关测试通过，保留的业务页面在独立开发宿主可使用。
- [x] 在配套 Shell 中加载同一业务前端构建产物，验证页面、业务请求、认证、共享依赖和主题继承；按前端规范查看相关截图。
- [x] 复用已有浏览器与联邦加载接缝，提供可重复执行的升级验证入口；明确 HTTP mock 和真实后端验证各自覆盖范围。
- [x] 交付前端升级清单、参考差异、验证命令与结果，说明环境内配套切换及发布入口登记的要求。
