# 文件保留与治理规格

Status: ready-for-agent

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准（「系统构成」中的 Storage Purpose、File Retention、Restore）。核心取舍由 [ADR-0026](../../docs/adr/0026-file-retention-two-phase-delete.md) 记录。依赖 `forge-sdk-storage` 与 `forge-sdk-scheduling`。

## 问题陈述

对象存储中的文件会持续累积：未确认的上传、被替换的版本、导入失败留下的临时文件，以及业务数据已不存在的孤儿文件都会占用租户配额。当前 Storage Purpose 只约束类型、大小与签名时长，没有保留期；`delete` 是立即物理删除，误删不可逆，也无法安全地自动清理仍被业务数据引用的文件。

## 解决方案

Storage Purpose 增加服务声明的保留期，配合引用检查与两阶段删除：

- 到期只把文件记录标记为失效，不立即删除对象；
- 7 天宽限期后才删除对象并释放配额；
- 删除前经 `FileReferenceChecker` SPI 检查业务引用；
- 未实现检查器、检查异常或超时，一律跳过删除并告警；
- 逻辑删除的业务行仍算引用；
- v1 不引入 Legal Hold，但状态设计为可扩展。

保留期的目标是存储卫生，清理孤儿文件；被业务数据引用的文件不因保留期删除。

## 用户故事

1. 作为业务服务开发者，我想为 Storage Purpose 声明保留期，以便该用途的文件按统一策略清理。
2. 作为业务服务开发者，我想让未声明保留期的用途永久保留，以便不误删需要长期保存的文件。
3. 作为平台管理员，我想让保留期由服务声明且租户不能修改，以便跨租户行为一致。
4. 作为业务服务开发者，我想让到期文件先进入失效状态，以便在宽限期内还可恢复或延长。
5. 作为业务服务开发者，我想在删除前检查业务引用，以便不删掉仍被订单、合同等数据引用的文件。
6. 作为业务服务开发者，我想在检查器未实现或异常时跳过删除，以便安全兜底。
7. 作为业务服务开发者，我想让逻辑删除的业务行仍算引用，以便 Restore 后附件仍可用。
8. 作为运维人员，我想在清理任务中看到跳过与失败的原因，以便定位配置问题。
9. 作为租户管理员，我想让过期文件在物理删除后才释放配额，以便用量反映真实存储。
10. 作为审计员，我想看到文件失效、物理删除与保留期延长的事件，以便追溯删除原因。
11. 作为业务服务开发者，我想让清理任务按用途隔离失败，以便一个用途出错不影响其他用途。
12. 作为平台管理员，我想为将来的 Legal Hold 预留状态，以便合规冻结时不用改表结构。

## 实现决策

- Storage Purpose 增加可选 `retentionDays`，大于零；未声明表示永久保留。校验在服务启动时执行。
- `forge_storage_object` 增加生命周期状态、保留截止时间与失效时间；状态至少包含 `STORED`、`EXPIRED`、`PURGE_PENDING`、`DELETED`，枚举可扩展以容纳 `HELD`。
- 到期处理只把状态改为 `EXPIRED` 并记录失效时间，不删除 S3 对象；宽限期固定 7 天。
- SDK 提供 `FileReferenceChecker` SPI，批量接收候选对象 ID，返回仍被引用的对象 ID。实现方使用自己的库与租户上下文查询。
- 清理任务在各业务服务内按 Tenant 运行，按用途分批处理；单个用途失败不影响其他用途。
- 未实现检查器、检查抛出异常或超时：跳过该批删除并告警，不按“无引用”处理。
- 逻辑删除的业务行仍算引用；引用检查应覆盖它们。
- 物理删除时删除 S3 对象与文件记录，并释放配额；宽限期内仍计入已用容量。
- 审计记录 `storage.expire`、`storage.purge`、`storage.retentionExtend`；不记录文件内容。
- v1 不实现 Legal Hold 的管理界面与权限，只保留状态位与扩展点。

## 测试决策

- 好的测试只验证外部行为：文件状态迁移、S3 对象是否存在、配额数值、审计事件；不直接断言清理任务的内部循环。
- 首选接缝是存储 SDK 的公开 API 加清理任务入口，配合假时钟与假引用检查器；这样能覆盖到期、宽限、跳过与删除四种路径。
- 真实 S3 行为沿用现有对象存储集成测试的容器接缝，不新增存储抽象。
- 引用检查异常与未实现两种路径都要有测试，断言“没有删除”而不是“抛异常”。
- 参考现有测试：`ObjectStorageTest`、`StoragePurposeTest`、租户定时任务相关测试。
- 前端本规格不新增页面，测试以 SDK 与任务为主。

## 不在范围

- 合规删除：即使被业务引用也在到期后删除。
- Legal Hold 的管理界面、权限与流程。
- 租户按用途覆盖保留期。
- 文件访问/下载审计。
- 文件预览、缩略图、水印或病毒扫描执行器。
- 恢复已物理删除的对象。

## 补充说明

- 保留期只解决孤儿文件与过期临时文件；被业务数据引用的文件会一直保留，这是有意为之。
- 若未来需要合规删除，增加 Purpose 级 `compliance` 模式，并单独设计业务侧的缺失态展示，不改变默认语义。
- 清理任务是租户任务，平台不跨服务删除文件。
