# 字段脱敏规格

Status: ready-for-agent

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准（「数据安全」一节）。核心取舍由 [ADR-0025](../../docs/adr/0025-field-masking-scope-and-no-raw-exception.md) 记录。依赖 Resource Manifest、`forge-sdk-security`、`forge-sdk-io` 与 IAM。

## 问题陈述

业务数据中的手机号、身份证、银行卡、姓名等字段，会以明文出现在导出文件、运行日志和部分在线接口中。平台没有字段级登记、分级与统一规则：

- 业务服务各自实现脱敏，口径不一致，合规检查无法回答“哪些字段被脱敏、按什么规则”；
- 导出缺少失败关闭策略，规则缺失时容易按明文导出；
- 日志中的敏感参数没有统一处理；
- 在线接口要么完全不脱敏，要么由各服务临时处理，无法审计“谁看了原文”。

## 解决方案

平台提供字段级脱敏，与行级 Data Policy 正交：

- Business Service 在 Resource Manifest 声明敏感字段、字段路径与数据分级（L1–L4）；
- 平台预置脱敏规则，Tenant 只能为字段选择或覆盖规则，不能编写表达式或正则；
- 导出、日志与声明的在线接口共用同一规则引擎；
- 导出缺规则时任务失败，日志不输出原值，在线缺规则时响应失败；
- 平台不提供“按角色自动返回原文”的例外；业务确需展示原文时，提供专用操作、单独授权并写审计；
- L4 字段默认禁止导出。

## 用户故事

1. 作为平台管理员，我想定义 L1–L4 数据分级及每级的默认规则，以便统一全平台的合规口径。
2. 作为平台管理员，我想维护固定的脱敏策略库，以便各服务复用同一套算法。
3. 作为租户管理员，我想为敏感字段选择或覆盖脱敏规则，以便满足本租户的合规要求。
4. 作为业务服务开发者，我想在 Resource Manifest 声明敏感字段，以便平台统一识别，而不是靠人工登记。
5. 作为业务服务开发者，我想在 DTO 字段上标注敏感字段，以便在线响应自动脱敏。
6. 作为业务服务开发者，我想让导出管线自动套用规则，以便不手写脱敏代码。
7. 作为业务服务开发者，我想让日志自动脱敏，以便日志中不出现明文 PII。
8. 作为业务服务开发者，我想在导出缺少规则时让任务失败，以便不会误导出明文。
9. 作为业务服务开发者，我想在线接口缺少规则时让响应失败，以便不会静默泄露。
10. 作为租户管理员，我想预览规则对样例值的效果，以便确认脱敏结果符合预期。
11. 作为审计员，我想看到脱敏规则、字段登记和原文查看的记录，以便追溯谁在何时改了什么、看了什么。
12. 作为业务服务开发者，我想提供受控的“查看原文”操作，以便在业务确有必要时展示原文。
13. 作为平台管理员，我想让 L4 字段默认禁止导出，以便满足最高等级的合规要求。
14. 作为业务服务开发者，我想在启动或上报清单时校验敏感字段声明与规则引用，以便尽早发现配置错误。
15. 作为租户管理员，我想让被引用的规则不能被删除，以便避免线上脱敏突然失败。
16. 作为业务服务开发者，我想让未声明的字段保持原样，以便明确登记责任边界。
17. 作为租户管理员，我想在列表、详情和导出中看到一致的脱敏结果，以便不会因入口不同而泄露。

## 实现决策

- Resource Manifest 新增 `sensitiveFields` 声明：字段路径、数据分级、可选默认规则。SDK 同时支持注解扫描生成声明，与 Permission Code 的收集方式一致。
- 数据分级固定为 L1 公开、L2 内部、L3 敏感、L4 极敏感；级别只决定默认规则与导出限制，不参与功能权限或数据权限判断。
- 脱敏规则只由固定策略库组合：`mask_middle`、`mask_tail4`、`keepFirst(n)`、`replace`、`email`、`phone`、`idcard`、`bankcard`、`name`。平台管理员维护规则，Tenant 只能选择规则，不能新增表达式或正则。
- 三条执行通道共用同一规则引擎：
  - 导出：SDK 导出管线在写单元格前取字段策略并脱敏；
  - 日志：Logback converter 按注册的字段名/参数名替换原值；
  - 在线：Jackson 序列化器按注解脱敏。
- 失败语义：导出缺规则或规则执行失败时任务失败；日志缺规则时丢弃原值并告警，不阻断请求；在线缺规则时整次响应失败。
- 不提供按角色或权限码自动返回原文的例外。需要原文时由业务服务提供专用操作，使用独立 Permission Code 并写审计。
- 规则与字段声明在启动、Manifest 上报和保存规则时校验；被字段引用的规则不能删除。
- IAM 新增数据安全子域：数据分级、脱敏规则、敏感字段登记、租户规则覆盖与预览。
- Shell 新增租户端“数据安全”页，平台运营端提供分级与规则预置管理。
- 审计动作包括字段登记变更、规则变更、租户覆盖变更与原文查看；审计详情本身不得包含原文。
- SDK 公共 API 包括敏感字段注解、脱敏引擎与导出策略端口；按 semver 管理。

## 测试决策

- 好的测试只验证外部行为：HTTP 响应中的字段值、导出文件中的单元格、日志事件中的文本、IAM 配置接口的返回；不直接断言 Jackson 注解或引擎内部方法。
- 首选接缝是 demo-service 的真实 HTTP 响应与导出文件，其次是 IAM 配置接口。这样一处接缝同时覆盖 Manifest 声明、规则查找与执行。
- 日志接缝使用日志捕获，断言敏感值不出现、非敏感值保持原样。
- 策略引擎允许单元测试，因为它是纯函数；但端到端行为不依赖单元测试证明。
- 参考现有测试：`OrderApiTest`（HTTP 行为）、`ObjectStorageTest`（文件）、`AuditTest`（审计）、`RoleManagementTest`（IAM 配置与权限）。
- ArchUnit 增加一条规则：在线脱敏只能经统一序列化器，业务代码不得自行拼接掩码字符串。

## 不在范围

- 对未声明字段的全链路在线脱敏。
- 按角色、权限码或租户开关直接返回原文。
- 租户自定义表达式、正则或脚本。
- 加密、密钥管理与数据库静态脱敏。
- 历史数据回填与存量明文清洗。
- MQ 消息体与通知内容的脱敏。

## 补充说明

- 改动 Manifest 结构需要升 `forge.manifest.version`，并按 SDK 接入指南同步模板。
- 策略库后续可以新增策略，但新增策略由平台发布，不开放给租户。
- 若未来确需合规删除或更宽的在线脱敏，另立 ADR，不在本规格内扩展。
