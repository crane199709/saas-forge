# 失败响应追踪日志

## 已确认的结果

- 本仓库服务产生的失败响应带有 traceId 时，必须有可按该 ID 检索的运行日志；成功请求不逐条记录。
- 4xx 用 INFO 单行摘要，包含请求方法、路由、HTTP 状态、业务错误码和响应中的 traceId，不带异常堆栈。
- 5xx 保留既有 WARN/ERROR 级别与异常堆栈；原先没有记录的 5xx 补充记录。
- 保留已有租户、成员日志上下文，不读取请求体、凭证或完整查询参数，不输出 errorMessage、userTip 或校验值。
- MVC 优先使用路由模板；容器错误转发使用原请求路径；路径移除查询部分、限制长度并处理控制字符。
- 错误由产生它的服务记录；网关只记录本地产生的失败，透传下游错误时不额外记录。
- 同一服务同一失败只记录一次，容器转发及安全处理器均需覆盖。
- 沿用现有日志输出和接口响应格式，不新增采集系统、持久化或审计功能。

## 验收

- 覆盖业务/参数校验 400、认证 401、权限 403、路由 404、限流 429、未知异常 500、依赖不可用 503。
- 断言日志级别、摘要条数、响应与日志 traceId 一致；5xx 保留堆栈，4xx 不打印堆栈。
- 覆盖 Servlet 安全直接写出、真实容器 /error 转发和网关响应式错误出口。
- 验证成功请求和下游错误透传不产生失败摘要，摘要不包含请求体、Token、密码或查询值。

## 边界

仅对修复后产生的请求生效，无法补回过去没有记录的日志。日志检索仍受部署环境的日志级别和保留策略约束。
