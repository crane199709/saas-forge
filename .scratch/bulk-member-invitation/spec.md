# 批量邀请规格

Status: ready-for-agent

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准。本规格的决策经 2026-11-09 的设计拷问逐条确认，未单独记录 ADR：不接入 Import Task 的决定以后可以只替换前端入口来改变，不算难以逆转。

## 1. 背景与目标

成员页只能逐个邀请（`POST /members/invitations` 每次一个联系方式）。客户入驻时需要一次加入大量成员，并按人指定角色和主部门。

目标：Tenant 的管理员在 tenant-app 成员页上传 Excel，一次发起最多 500 个邀请。每行的语义与单个邀请完全一致。

非目标：

- 管理员代设密码或直接创建账号。Identity 是全局的（ADR-0002），租户管理员无权设置其凭证。
- 平台运营端代加成员、部门级委派。
- 姓名、岗位、兼任部门、Extended Attribute 列。
- CSV。
- 断点续传、服务端异步执行。

## 2. 方案

主体在 `frontend/apps/tenant-app`：浏览器解析文件，以固定并发 3 逐行调用现有邀请接口。权限、成员数配额、审计和发送全部沿用接口现有逻辑。

后端只改一处：`POST /members/invitations` 的响应增加布尔字段 `resent`，`true` 表示这次是给仍为 invited 的 Membership 重发，用于区分结果。`MemberService.invite` 在持有租户锁时已算出邀请前后的未离开成员数：人数不变即重发，人数增加即新邀请或已离开成员重新邀请，不需要新查询。字段是增量的，单个邀请对话框不受影响。

不接入 Import Task 的原因：

- forge-iam 没有存储配置，接入后启动依赖 S3，而它属于 Platform Core。
- `IoTaskMapper` 依赖租户拦截与 RLS，forge-iam 不启用 RLS（见 `V8__organization.sql`）。
- `ExcelIo` 依赖的 `ReferenceData` 客户端要通过 HTTP 调用 forge-iam 自身。
- `writer` 在单一事务内执行，事务回滚时已发出的邀请无法收回；每行各自成败更贴合发送不可撤回的事实。

依赖关系：不依赖 [data-import-export](../data-import-export/spec.md) 与 [import-confirmation](../import-confirmation/spec.md)，也不使用 `ImportDialog`。

## 3. 文件与模板

- 只接受 `.xlsx`，单次最多 500 个数据行，超出时整个文件拒收并提示拆分。表头与模板不符时整个文件拒收，全空行忽略。
- 模板由前端生成，不带下拉。解析库在工单中调研选定，须按需加载，不进入首屏。

| 列 | 必填 | 规则 |
|---|---|---|
| 联系方式 | 是 | 校验规则与 `SendCodeRequest.TARGET_PATTERN` 一致，最长 254 字符；文件内重复报错，邮箱不区分大小写 |
| 角色 | 否 | 按角色名称匹配，多个用 `、` 分隔；不允许 Owner；需要 `iam:role:manage` |
| 主部门 | 否 | 按部门名称从根到本级用 `/` 拼接的完整路径匹配，如 `总部/研发部/后端组`；需要 `iam:org:manage` |

角色名称与部门路径在库中没有唯一约束，匹配到多条时该行报错，不做猜测。匹配用的角色和部门列表沿用单个邀请对话框的接口；Department 的 `path` 字段是 ID 路径，名称路径由 `parentId` 拼出。

## 4. 流程

1. 成员页提供批量邀请入口，需要 `iam:member:manage`。
2. 上传后做本地校验，显示预览：将邀请 N 人、M 行有错误及明细。
3. 确认后只发送有效行，错误行直接进入失败清单。没有有效行时不能确认。
4. 发送中显示进度。
5. 结束后显示各结果的计数，可下载失败清单，并刷新成员列表。

## 5. 每行结果

| 情况 | 结果 |
|---|---|
| 接口成功且 `resent` 为 `false`（新邀请、`left` 重新邀请） | 已邀请 |
| 接口成功且 `resent` 为 `true`（`invited` 重发） | 已重发 |
| `member.alreadyMember` | 已是成员 |
| 本地校验错误、`member.quotaExceeded`、其他 4xx、5xx、网络错误、429 | 失败 |
| 用户停止后尚未发出的行 | 未处理 |

- 任何失败都只影响该行，后面的行继续。配额用尽时也继续，因为 `invited` 的行重发不占配额。
- 不自动重试：5xx 时无法判断邮件是否已发出，重试可能造成重复发送。

失败清单包含「失败」和「未处理」的行，格式与模板相同，末尾多一列「失败原因」。上传时忽略这一列，修正后可直接重传。

## 6. 发送中途

- 发送期间弹窗不可关闭，刷新或关闭标签页时弹出浏览器离开提示。
- 「停止」后，已发出的请求等待完成，其余行标为未处理。

## 7. 已知风险

- **滥用**：邀请发送没有服务端限额，试用租户可能用来发垃圾邮件，`invited` 的行重发也不受配额约束。现有接口已可被脚本以网关限流的速度调用，前端批量没有扩大服务端能力。如需限额，单独立项并同时覆盖单个邀请。
- **半途状态**：现有接口在 Membership 提交后才分配角色、部门并发送。后续步骤失败时成员已是 invited 但未收到邮件，也没有审计记录。批量中该行显示失败，重传可补发。
- **进度丢失**：浏览器崩溃后进度不保留。重传原文件时，已邀请的人会再收到一封，已接受的人显示「已是成员」。

## 8. 验收

- forge-iam 集成测试（`MemberManagementTest`）覆盖 `resent`：新邀请和已离开成员重新邀请为 `false`，重复邀请 invited 成员为 `true`。
- Vitest（`MemberPage` 或拆出的组件）覆盖：文件拒收条件、联系方式校验与重复、角色和部门的匹配与歧义、缺少权限、各行结果、停止、失败清单往返。
- Playwright 覆盖上传、预览、确认发送、结果与失败清单下载。接口用模拟响应，真实后端行为由邀请接口的集成测试覆盖。
- 新增文案同时写入 tenant-app 的各语言 locale。
