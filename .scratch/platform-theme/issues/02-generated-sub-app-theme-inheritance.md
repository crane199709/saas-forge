# 02: 脚手架生成的 Sub-App 继承统一主题

**What to build:** 开发者通过 sub-app-kit 生成 Sub-App 后，独立开发与挂载到 Shell App 两种方式均使用平台统一的靛蓝 + Slate 浅色主题，无需自行复制或配置色板；已有工程的开发者能够依据明确的升级步骤保持相同约定。

**Blocked by:** 01（平台与现有 Sub-App 统一浅色主题）；需要其共享主题实现、组件交互样式与主题规范作为生成工程的验证基准。

**Status:** ready-for-agent

- [ ] 仓库内和仓库外两种生成方式均使用统一的宿主主题入口，并携带平台对应版本的 Sub-App 页面规范与生成工程说明；不在页面或模板复制一份独立色板。
- [ ] 对真实生成工程完成依赖安装、构建与启动验证；独立开发宿主实际呈现 `#4F46E5` 主色及 01 确定的 Slate 文字、背景、边框和填充，不依赖 Shell App 提供样式才显示正确。
- [ ] 生成工程独立开发时，实心主按钮的默认、悬停与按下状态均使用共享交互样式，白字对比度至少为 4.5:1；不能只验证主题变量存在而遗漏实际组件状态。
- [ ] 将生成工程的联邦产物挂载到 Shell App 后，按钮、文字与页面内容继承宿主主题；通过诊断切色验证 Sub-App 同步变化，中性色保持统一。
- [ ] 生成工程遵守只读 Theme Token 的边界，不覆盖平台全局主题；保留现有对修改文档根节点、全局样式与主题 token 的限制，不为换色放宽边界。
- [ ] 更新生成流程的自动化验证，覆盖两种生成方式的共享主题使用、新版规范分发与已有的拒绝覆盖行为；必要调整与规范、模板、接入指南及变更日志同步。
- [ ] 升级说明分别讲清已部署 Sub-App 读取新版 Shell App 主题，以及独立开发宿主升级配套共享 UI、kit 和规范副本的步骤；明确写死颜色的既有页面需自行调整，不承诺自动修复外部工程。
- [ ] 完成真实生成工程的浏览器验证与 1440、1024 两档截图走查，检查独立开发和 Shell App 挂载两种方式，结果记录在工单验收说明中。
- [ ] 脚手架相关测试、构建、类型、样式及格式检查通过；最后对完整改动运行一次所需的前端回归与视觉验证，保留其他任务的既有修改。
- [ ] 本工单仅在临时验证工程中演示生成、构建与挂载流程，不自动修改、重新生成或发布仓库外已有工程。
