# 导入回滚规格

Status: resolved

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准（「导入导出」一节）。核心取舍由 [ADR-0027](../../docs/adr/0027-import-rollback-restores-overwritten-values.md) 记录。依赖 [data-import-export](../data-import-export/spec.md) 与 `forge-sdk-io`。

## 问题陈述

覆盖导入会改写已有业务数据。导入确认后一旦发现映射错误、数据源错误或误操作，用户无法回滚：

- 只能逐条手工恢复，数据量大时不可行；
- 无法判断哪些记录在导入后又被修改，手工恢复可能覆盖别人的新修改；
- 没有冲突报告，管理员无法在回滚前评估影响；
- 审计只记录“导入成功”，无法回答“这次导入改了什么、回滚了什么”。

## 解决方案

SDK 的导入能力增加“覆盖前快照 + 回滚”：

- 覆盖导入在写库前保存将被覆盖的数据；
- 回滚只恢复被覆盖的旧值，不删除该次导入新增的数据；
- 回滚前生成冲突报告：记录在导入后又被修改或被后续导入覆盖时，默认阻断；
- 管理员显式确认后，可以跳过冲突记录、回滚其余记录；
- 回滚按记录执行，失败可重试，已恢复的不重复；
- 快照保留 90 天，可由服务调整；
- 回滚是独立权限，并写独立审计。

## 实现决策

- `forge-sdk-io` 增加覆盖导入快照表，随服务迁移创建，带标准列与租户隔离，并接入租户清理。
- 快照在导入确认写入前创建，保存记录主键与本次导入会覆盖的字段旧值；不保存新增行，也不保存未受导入影响的字段。
- 回滚只恢复快照中的字段值，不删除该次导入新增的行。
- 冲突判定基于记录在导入后的修改（`updated_at` 或版本列）以及后续导入任务对同一记录的覆盖；冲突记录写入报告，默认阻断。
- 回滚接口分两步：预览冲突报告；执行回滚，支持 `skipConflicts`。执行按记录逐条处理，记录成功/失败/跳过，可重试，已成功的不重复处理。
- 快照保留 90 天，默认由 SDK 清理任务删除；过期任务不可回滚，只保留任务记录。
- 新增独立 Permission Code 与审计动作 `io.importRollback`；审计记录任务号、恢复数、跳过数与失败数。
- 前端在 `@crane199709/ui` 提供导入历史与回滚对话框组件，业务服务在自己的页面接入。
- 回滚不改变 Import Task 的原始状态，只追加回滚状态与次数。

## 测试决策

- 好的测试只验证外部行为：导入后回滚的数据库结果、冲突报告内容、审计事件与权限拒绝；不直接断言快照表的行结构。
- 首选接缝是 demo-service 的 HTTP 接口：提交导入、确认、预览冲突、执行回滚，一次覆盖 SDK 与业务服务集成。
- 冲突场景需要真实修改记录后再回滚，验证默认阻断；确认跳过后再验证其余记录恢复。
- 幂等与重试用同一接口重复调用验证，不测内部重试实现。
- 参考现有测试：`import-confirmation` 的 Playwright 用例、`OrderApiTest`、`ObjectStorageTest`、`AuditTest`。
- 前端组件用 Vitest + mocked client 覆盖冲突报告与确认流程，再补一条 Playwright 真实链路。

## 不在范围

- 撤销该次导入新增的行。
- 跨服务或跨导入任务的联合回滚。
- 永久可回滚；快照过期后不承诺恢复。
- 回滚导入后的人工修改。
- 无覆盖的追加导入回滚。

## 补充说明

- 回滚是数据修复操作，不是 Restore；两者术语与审计动作必须分开。
- 如果业务服务没有配置快照或快照已过期，导入详情应明确显示“不可回滚”，而不是隐藏入口。
- 快照保留期由服务配置，默认 90 天，前端展示实际截止时间。

## 实现与最终验收（2026-11-13）

集成分支：`codex/import-rollback`。最终代码验收点：`927fbedb5f72e6669588f57047b0ddf031abc8ea`；后续收尾只更新本规格。四张工单均已 resolved：[快照](issues/01-import-backup.md)、[预览](issues/02-conflict-preview.md)、[执行与审计](issues/03-rollback-execution.md)、[界面与真实验收](issues/04-ui-and-acceptance.md)。

- SDK 在覆盖前保存受影响字段，逐记录恢复与成功标记同事务，支持显式跳过冲突、失败重试和幂等；预览后的新修改或后续覆盖在执行锁内重新检查。保留当前租户、本人任务与当前数据权限边界。
- Demo 保留原追加导入，新增四列覆盖模型（可选订单 ID）；回滚只恢复标题、金额、客户来源，新增行、编号、状态与归属保留。回滚独立权限为 `order:importRollback`。
- 共享 UI 提供导入历史和两阶段回滚对话框，展示原任务状态、回滚结果、实际截止时间、不可用原因和逐条冲突。历史按持久化模型选择确认入口，部分回滚后到期仍保留历史结果，全部恢复显示已回滚。
- 快照默认保留 90 天，可配置；清理先保留已提交进度，再清空旧值并逻辑删除，覆盖停用租户及中断后直接到期的情况。已有服务按顺序新增迁移复制 `upgrade-import-backup.sql`、`upgrade-import-rollback-preview.sql`、`upgrade-import-rollback-execution.sql`（demo V15–V17），不改旧迁移；新服务使用当前 `schema.sql`。
