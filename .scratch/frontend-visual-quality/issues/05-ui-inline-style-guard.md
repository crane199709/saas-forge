# 05: `@forge/ui` 内联样式强制校验

**What to build:** 给 `@forge/ui` 建一道机器校验，让「样式只写主题 token」这条约定第一次真的能被 CI 拦住。该包全部用 `h()` 内联样式，现有样式规则只扫 `.vue` 与 `.css`，是当前最大的规范盲区。见[规格 4.6](../spec.md#46-强制机制)。

**Blocked by:** 01、02、03、04（工具会扫全包，先让前面的改动落地再开规则，避免误报混进本次改动）

**Status:** ready-for-agent

- [ ] 新增一个独立工具，用 TypeScript 编译器 API 静态扫描 `@forge/ui` 中 `h()` 调用里 style 对象的字面量色值与长度值；不用正则（AST 能区分样式字面量与注释里的值）
- [ ] 工具纳入前端工具脚本的类型检查范围，并在前端工作区加一个 `lint:ui` 脚本
- [ ] 前端 CI 在既有样式检查步骤之后新增该步骤
- [ ] **只在 monorepo 内启用**，不进 `sub-app-kit` 的发布物；在 `frontend-design.md` 里写明「验证一个版本周期后再由 kit 依赖」的后续动作
- [ ] 不修改既有的 `.vue`/`.css` 样式规则，本次只补 `h()` 这个盲区
- [ ] 修掉首次运行报出的既有违规，不改动视觉结果（若某处必须保留字面量，在工具里加显式豁免而不是放宽规则）
- [ ] 误报处理：若 AST 对某些写法判断不准，先放宽为 warning 并在 `frontend-design.md` 记录待办，**不退回复正则方案**
- [ ] 测试：工具自身的单元测试覆盖「该报的报、不该报的不报」（`var()`、`color-mix()`、常量引用不报；hex、`rgb()`、`px` 报）
- [ ] `pnpm lint:ui`、`pnpm lint:style`、`pnpm typecheck`、`pnpm -r test` 通过，且视觉基线无变化
