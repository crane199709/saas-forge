# 07: 清理未被引用的视觉基线

**What to build:** 删除视觉基线目录中不再被任何用例引用的 PNG，并对齐基线数量与用例数量。

**Blocked by:** 无

**Status:** needs-triage

## 现象

`frontend/e2e/visual/__screenshots__/` 有 **229 个 PNG**，而视觉测试实际是 **215 个用例**（工单 04 合并后）。差额的 14 张从未被任何用例引用。

工单 05 的实现者顺带发现了这一点。这些文件不会让测试失败（Playwright 只找自己用到的文件名），但会：

- 让「改了几张基线」这类判断失真——评审时无法区分"用例减少了"与"基线没清"
- 增加仓库体积
- 让后来者误以为某些页面状态仍有视觉覆盖

## 待查

1. 逐张确认哪 14 张确实无引用（不能只看数量差：用例可能被改名、文件也可能被同名覆盖）。
2. 确认它们对应的用例是**被删除**还是**被改名**——若是改名，说明有页面状态悄悄失去了覆盖，那比多余文件更值得处理。
3. 确认没有 CI 或脚本直接引用这些文件名。

## 验收标准

- 基线数量等于用例数量，且能说清每一个删除的文件原属哪个用例、为什么不再需要。
- 若发现"用例被删导致覆盖丢失"，单独开票恢复覆盖，而不是简单删文件了事。
- `pnpm test:visual` 全量通过。
