# 08: 模板冒烟 CI 任务

**What to build:** CI 任务在仓库外的空目录中，只用当前提交发布出来的制品生成并验证一个 Business Service 和一个 Sub-App，证明 SDK 在仓库外可用。这是本规格最高层的测试接缝，同时覆盖发布流程、BOM 完整性、archetype、前端脚手架、网关配置驱动和接入清单的可执行部分。见[规格 · Testing Decisions](../spec.md#testing-decisions)。

**Blocked by:** 02 网关按配置声明接入服务, 03 服务数据库准备脚本与平台侧接入清单, 05 后端工程模板与接入指南, 06 前端脚手架可在仓库外运行

**Status:** ready-for-agent

- [ ] 把当前提交的全部 Maven 制品与 npm 包发布到任务内临时本地仓库（复用 04 的发布流程）
- [ ] 在仓库外的空目录用 archetype 生成服务，Maven 只从临时本地仓库和公共仓库解析依赖，不读取 monorepo；运行它的 `verify` 并通过
- [ ] 复用主链路 E2E 的环境脚本拉起平台服务；按接入清单用 03 的脚本准备数据库、为新服务登记 Manifest 令牌、在网关配置中声明新前缀与路由
- [ ] 启动生成的服务：Manifest 上报成功；经网关调用示例接口，有权限的成员得到 200，没有权限的成员得到 403；`/<前缀>/internal/**` 经网关被拒
- [ ] 在仓库外的空目录，用临时 npm registry 中的 `@forge/sub-app-kit` 生成 Sub-App，安装依赖后 lint、类型检查与构建通过
- [ ] 作为独立工作流在 PR 与 main 上运行，失败时保留日志；加入发布工作流的质量门
- [ ] 本地可用一条命令复现，写入接入指南的「维护者」一节
