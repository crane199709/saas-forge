# 字典变更历史规格

Status: resolved

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准（「参考数据」一节）：Dictionary、Dictionary Item、Extensible Dictionary、Dictionary Change History。本规格不单独记录 ADR，因为版本历史是追加能力，移除不影响既有语义。

## 问题陈述

Tenant 对 Extensible Dictionary 的修改（改名、调排序、新增自定义项、停用/启用）只留下当前状态和零散的审计事件。管理员无法回答：

- 这个字典过去长什么样；
- 某个显示名是什么时候、被谁改的；
- 两个时间点之间增加了哪些项、移除了哪些项、改了哪些项；
- 误改后要恢复成什么值。

现有审计事件只有新值，没有旧值与完整快照，不能可靠重建历史。

## 解决方案

为 Tenant 对 Dictionary 的覆盖设置保存逐次快照：

- 只有有效变更才生成版本，无变化的保存不产生噪声；
- 每个版本保存该字典当时的完整租户覆盖集合；
- 提供版本列表、单版本查看与任意两版 diff；
- Manifest 中服务声明的内置项只作上下文标注，不属于快照；
- v1 只读，不提供回滚。

## 用户故事

1. 作为租户管理员，我想在字典页面看到变更历史，以便知道这个字典被改过几次。
2. 作为租户管理员，我想看到每个版本的变更人、时间和变更摘要，以便追溯责任。
3. 作为租户管理员，我想查看某个版本的完整租户覆盖内容，以便知道当时的值。
4. 作为租户管理员，我想比较任意两个版本，以便看清增加、移除和修改的项。
5. 作为租户管理员，我想在只改了名称或排序时看到明确差异，以便确认改动范围。
6. 作为租户管理员，我想让无变化的保存不生成版本，以便历史列表不被噪声淹没。
7. 作为租户管理员，我想让服务声明的内置项只作为上下文标注，以便区分“服务改的”和“租户改的”。
8. 作为审计员，我想通过权限码查看字典历史，以便只读审计而不改配置。
9. 作为业务服务开发者，我想让历史只记录租户覆盖，以便服务升级不污染租户历史。
10. 作为租户管理员，我想在版本详情里看到当前值，以便和历史值对照。
11. 作为租户管理员，我想让历史随租户删除一起清理，以便满足数据清理要求。

## 实现决策

- 新增 `dictionary_history` 表：租户、服务、字典、版本号、完整覆盖快照、变更摘要、变更人与时间；带标准列与租户隔离，接入租户清理。
- 版本号按“租户 + 服务 + 字典”递增；快照内容是当时的租户覆盖项集合，不包含 Manifest 内置项。
- 在字典项新增、改名、改排序、停用、启用的有效变更后追加版本；值未变化时不追加。
- 提供列表、单版本与两版 diff 接口；diff 返回 added、removed、changed 三类。
- 前端在现有字典页面增加“变更历史”页签，支持版本列表与 diff 对照；不做独立页面。
- 查看历史使用独立 Permission Code；审计仍按现有 `dictionary.item*` 记录，历史表不替代审计。
- 不提供回滚；如未来需要，另行设计并评估与 Manifest 变更的关系。
- 不记录 Parameter 覆盖历史，Parameter 仍由现有审计与版本号覆盖。

## 测试决策

- 好的测试只验证外部行为：变更后历史列表的版本数、diff 内容、无变化保存不新增版本；不直接断言快照表的 JSON 结构。
- 首选接缝是 IAM 的字典管理 HTTP 接口：创建、改名、停用、启停后查询历史与 diff，覆盖服务层与持久化。
- 跨租户隔离与权限拒绝在同一接缝验证。
- 前端用 Vitest + mocked client 覆盖历史列表与 diff 展示；Playwright 补一条真实修改后查看历史的链路。
- 参考现有测试：`ReferenceDataTest`、`DictionaryPage.spec.ts`、审计相关测试。

## 不在范围

- 字典回滚。
- Manifest 中字典声明演进的历史。
- Parameter 覆盖历史。
- 跨服务或全平台字典变更总览。
- 历史数据的导入与回填。

## 补充说明

- 历史快照是产品能力，审计事件仍是安全记录，两者并存但不互相替代。
- 字典项数量有限，v1 全部保留；若后续体积成为问题，再增加归档策略，不改变 diff 语义。
- 服务删除某个内置项后，租户覆盖中仍可能存在该编码；历史按当时快照展示，当前列表按现有规则隐藏。
