# 导入导出规格

Status: ready-for-agent

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准（「导入导出」一节）。本规格的决策经 2026-11-04 的设计拷问逐条确认（Q57–Q71），未单独记录 ADR。依赖 [reference-data](../reference-data/spec.md)（字典校验与名称）与 [tenant-scheduling](../tenant-scheduling/spec.md)（中断任务收尾、结果文件清理）。

## 1. 背景与目标

B 端业务普遍需要 Excel 批量导入与导出，SDK 目前只有对象存储：`ObjectStorage` 的上传、下载都由客户端凭预签名 URL 直连存储，服务端没有读写对象内容的入口。

目标：新 SDK 模块 `forge-sdk-io`，让 Business Service 用一个带注解的 `record` 描述导入导出模型，异步执行 Import Task 与 Export Task，自动生成 Import Template，校验失败时给出 Error Report；前端提供通用组件。

非目标：CSV、Word、PDF；部分成功的导入；同步导入导出；跨服务的任务中心；管理员查看他人任务；自动重试。

## 2. 模型与格式

- 只支持 `.xlsx`。导入模型与导出模型都用带注解的 `record` 描述列名、顺序、必填与字典字段。
- 读写必须流式，内存占用不随行数线性增长；Excel 库（Apache POI 流式 API 或其上的封装）在首个工单中调研选定。
- 字典列：导出输出可选项或已停用项的名称（文件面向人阅读，是「接口响应不补名称」的例外）；导入按名称在当前租户该字典的可选项中匹配并转为编码，不接受编码（名称唯一由 reference-data 保证）。

## 3. 任务

### 3.1 记录与状态

- 任务记录存在业务服务自己的 schema，表由 SDK 提供（与 `forge_storage_object` 同样做法），带标准列与租户隔离。
- 状态：等待 → 执行中 → 成功 / 失败；记录类型、提交人（Membership）、行数、失败原因、结果文件对象 ID、心跳时间。
- 任务只对提交人可见：查询状态与获取下载票据都校验提交人。

### 3.2 执行

- 由接收提交的实例在本地有界线程池中执行，执行中定期更新心跳；线程池已满时拒绝提交，返回 `io.busy`。
- SDK 注册一个 Global Task，把心跳超时的「执行中」任务标记为失败（原因「执行中断，请重新提交」）。不自动重试，不经 MQ 分发。
- 任务执行时带上提交时的租户、Membership 与授权上下文；如何把 ABAC 所需的主体属性带入异步线程，在工单中对照 `forge-sdk-abac` 确认。

### 3.3 Import Task

1. 用户经现有预签名直传上传文件，业务接口以对象 ID 提交任务。
2. 解析并校验全部行：字段校验、`@DictionaryValue`、业务方提供的校验；任一行出错即一行不写，生成 Error Report（原文件每行后附错误原因列）。
3. 全部通过后在一个事务中写入。
- 单次行数上限可配置（参考 1 万行）。
- 源文件在任务结束后立即删除。

### 3.4 Export Task

- 沿用对应列表接口的查询条件与 Data Policy，导出范围与提交时该成员在列表中可见的数据一致。
- 单次行数上限可配置（参考 10 万行），超出时提示缩小筛选范围。

### 3.5 Import Template

由导入模型自动生成：表头、列宽、必填标记；字典列加 Excel 下拉校验，选项为当前租户该字典的可选项名称。

## 4. 存储

- `ObjectStorage` 新增服务端入口：打开对象内容流（读导入文件）、由服务端写入对象（导出文件、Error Report）；都限制在当前租户前缀内，写入照常校验存储 Quota。
- 导出文件与 Error Report 计入 Quota，写入时配额不足则任务失败（`storage.quota_exceeded`）。
- 结果文件保留 7 天（可配置），由 SDK 注册的 Tenant Task 删除；任务记录保留，文件过期后不可下载。

## 5. 接口划分

- SDK 在每个业务服务中自动注册任务接口：列出自己的任务、查询状态、获取结果文件下载票据。
- 「下载模板」「提交导入」「提交导出」由业务方编写，挂自己的权限码与查询条件，调用 SDK 提交任务。

## 6. 审计

任务结束时由业务服务经 `forge-sdk-audit` 记录：`import.run`（行数、结果）、`export.run`（行数、查询条件摘要）。

## 7. 前端（`@crane199709/ui`）

- 导入对话框：下载模板、上传、进度、下载 Error Report。
- 导出按钮：提交、进度、完成后下载。
- 两者都带「最近任务」列表，调用所属服务的任务接口；不做 Shell 级的跨服务任务中心。

## 8. 验收（demo-service 订单）

- 订单导入含字典列「客户来源」：模板带下拉；按名称匹配；有错行时生成 Error Report 且不写入；全部通过时一次写入；超出行数上限被拒。
- 订单导出带 Data Policy：导出范围与列表一致；字典列输出名称。
- 他人无法查看或下载任务结果；配额不足时导出失败；线程池满时提交返回 `io.busy`。
- 实例中断后心跳超时的任务被标记为失败；结果文件到期后被删除。
